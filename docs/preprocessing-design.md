# 전처리 파이프라인 설계 — 문서 특성 분석과 권장안

작성일: 2026-10-09 · 근거: 적재된 원문 전체 프로파일링(PDF 263개 11,405쪽 + HTML 21개). 프로파일 스크립트는 `scripts/profile_corpus.py`.

---

## 1. 기관별 문서 특성 (실측)

### 1.1 전체 규모

| 기관 | PDF 쪽수 | 표가 있는 쪽 | 텍스트층이 없는 이미지 쪽 | 비고 |
|---|---|---|---|---|
| EMA | 4,574 | 1,454 (32%) | 97 (2%, 위험관리계획 부록만) | 대부분 디지털 원본 |
| FDA | 6,183 | 1,057 (17%) | 407 (7%) + 오래된 OCR 텍스트층이 있는 스캔본 135쪽 | 라벨이 2,872쪽(46%) |
| HC | 648 + HTML 21개 | 288 (44%) | 0 | 심사 문서(SBD/RDS)는 HTML |

### 1.2 EMA

- **평가보고서(EPAR AR)는 텍스트층이 있는 디지털 원본입니다.** 처리가 어려운 이유는 OCR이 아니라 **표**입니다.
  - 전체 쪽의 40%에 표가 있습니다.
  - 병합 셀이 많습니다(예: 파라미터 1개가 Mean/SD/Median 행에 걸쳐 있음).
  - 세로선 없이 가로선만 있는 표가 있습니다.
  - 표 바로 아래에 각주가 붙습니다.
- **PDF 책갈피(bookmark)가 깊습니다.** 주 평가보고서는 책갈피가 100~150개, 깊이 4~5단계입니다. 이것을 섹션 트리로 그대로 쓸 수 있습니다.
  - `Discussion`·`Conclusion` 소제목이 문서당 7~11개 있어서, 기관 판단 부분을 구분하는 기준(말한 주체 규칙)이 그대로 작동합니다.
- **중복 허가로 받은 평가보고서(Eksunbi, Qoyvolma)는 거의 같은 문서입니다.** 이 보고서들은 책갈피가 없고, 모든 쪽에 "Medicinal product no longer authorised" 워터마크가 있습니다.
  - 그대로 색인하면 같은 내용이 검색 결과에 두 번 나옵니다. 거의 같은 문서를 걸러내는 처리가 필요합니다.
- **반복 머리말 비율이 0.84~1.00으로 높아서 쉽게 지울 수 있습니다.** 꼬리말 형식은 "Assessment report EMA/106045/2024 Page 48/168"입니다.
- **가림 처리 표지가 거의 없습니다**("CCI" 3건). 처음에 가림 처리로 의심했던 검은 상자는 표의 가로선이었습니다.

### 1.3 FDA

- **최근 리뷰의 '이미지 쪽'은 스캔본이 아닙니다.** 디지털 문서를 통째로 이미지로 바꾼 쪽입니다(144dpi, 깨끗한 활자).
  - **핵심 표가 이런 이미지 쪽에 들어 있는 경우가 많습니다.** 예를 들어 BMAB1200 통합 리뷰의 표 2 "Clinical Studies Submitted"가 이미지입니다.
  - 이미지 쪽 비율: 통합 리뷰(multidisciplineR) 113/694쪽, 품질 리뷰(chemR) 129/291쪽.
  - 품질 리뷰의 이미지 쪽은 체크박스 표(✓ Yes / ☐ No / ☒ N/A)라서, 체크 상태를 보존해야 합니다.
- **2009년 Stelara 리뷰는 진짜 스캔본입니다.** Acrobat "Paper Capture"로 만든 OCR 텍스트층이 들어 있지만, "t he"처럼 단어가 쪼개지는 오류가 있습니다. PDF 메타데이터의 producer 값으로 식별할 수 있습니다.
- **가림 처리 표지 `(b)(4)`가 891건, `(b)(6)`이 104건입니다.** 정규식으로 "비공개"를 표시할 수 있습니다.
- **통합 리뷰는 FDA 심사자가 쓴 문서입니다.** "Applicant's Position / FDA's Assessment" 같은 라벨이 없습니다.
  - 신청자의 주장은 "The Applicant states/proposed…" 같은 간접 인용으로 나옵니다.
  - 섹션마다 "Authors:"로 작성 심사자가 표시됩니다.
  - 5개 중 3개는 책갈피가 없어서, "2.2." 같은 번호 매긴 제목으로 섹션을 찾아야 합니다.
  - 모든 쪽에 "Reference ID: ……" 꼬리말이 있습니다(반복 비율 0.71).
- **라벨이 FDA 전체 쪽수의 46%(2,872쪽)를 차지합니다.** 보충 신청이 있을 때마다 라벨 전체가 새로 나오기 때문이고, Stelara 하나만 36개 판입니다.
  - 마지막 쪽의 포장 박스·용기 라벨 그림(이미지 51쪽)은 검색 가치가 낮습니다.
- **FDA 가이던스 초안에는 왼쪽 여백에 줄 번호가 있습니다**(89쪽). 제거해야 합니다.

### 1.4 HC

- **SBD·RDS·가이던스 요약은 HTML입니다.** 제목(h2/h3)과 표가 DOM 구조에 있으므로 PDF 처리가 필요 없습니다.
  - 바이오시밀러 SBD는 같은 양식입니다(Comparative Structural…, Characterization…, Manufacturing Process…).
- **제품설명서(PM)는 디지털 PDF이고, 책갈피가 100% 있습니다.**
  - 44%의 쪽에 표가 있습니다.
  - 그림 캡션("Figure G")이 꼬리말처럼 잡혀서 꼬리말 반복 비율이 낮습니다.
- **가이던스 PDF는 모든 쪽에 장식용 배경 이미지가 깔려 있지만, 텍스트층은 정상입니다.** 그래서 "이미지 면적이 크다"만으로 스캔본이라고 판단하면 오분류됩니다.

## 2. 제안 방식(PyMuPDF → 가벼운 OCR → 로컬 LLM) 평가

**방향은 맞습니다.** 싼 처리부터 하고, 실패한 부분만 비싼 처리로 넘기는 구조입니다. 다만 실측해 보니 보완할 점이 다섯 가지 있습니다.

| # | 문제 | 근거 | 보완 |
|---|---|---|---|
| 1 | **어려운 부분은 OCR보다 '표'입니다** | 텍스트층이 있는 쪽이 94%. 반면 표가 있는 쪽은 EMA 32%, HC 44% | PyMuPDF와 OCR 사이에 **표 구조 인식 단계**를 둡니다. PyMuPDF 기본 표 추출은 EMA PK 표에서 병합 셀 값을 3번 중복하고, `text` 방식으로는 숫자가 쪼개짐 |
| 2 | **가벼운 OCR은 글자만 읽고 구조를 잃습니다** | RapidOCR(CPU)은 신뢰도 0.97~0.99, 쪽당 약 2초. 하지만 표가 셀 나열로 바뀌고 체크박스(☒/☐)가 사라짐. 기본 모델이 중국어용이라 영어 띄어쓰기도 사라짐 | OCR 다음에 **이미지 표 구조 인식**(TableFormer / RapidTable / PP-Structure)을 붙입니다. 영어 인식 모델을 사용합니다 |
| 3 | **"어려운 부분"의 판정 기준이 정해져 있지 않습니다** | 이미지 면적만 보면 HC 가이던스(배경 이미지)를 스캔본으로 잘못 판정. 오래된 OCR 텍스트층은 텍스트가 있어도 품질이 낮음 | **쪽 단위 라우터**가 측정 가능한 신호로 판정합니다(3장). 판정 근거는 메타데이터로 남깁니다 |
| 4 | **qwen3.5:9B를 숫자에 바로 쓰면 위험합니다** | 범용 비전-언어 모델(VLM)은 표를 '그럴듯하게' 복원하면서 숫자를 틀릴 수 있음(PK 수치, 신뢰구간). 이미지 입력은 Ollama 빌드에 비전 인코더가 포함돼 있어야 가능(`ollama show qwen3.5:9b`로 확인) | 최후의 단계로만 쓰고, **출력 숫자를 OCR 토큰과 대조해 일치할 때만 채택**합니다. 쪽→마크다운 변환은 문서 전용 소형 VLM(granite-docling 258M, PaddleOCR-VL 0.9B)이 더 빠르고 안정적인 후보 |
| 5 | **"무엇을 처리할지"가 속도를 더 크게 좌우합니다** | FDA 라벨 2,872쪽 중 대부분은 이전 판. 중복 허가 평가보고서는 거의 같은 문서. 포장 그림은 가치가 낮음 | **처리 대상 선별 단계**를 맨 앞에 둡니다(4장). 이것만으로 FDA 처리량이 절반 가까이 줄어듦 |

**라이선스 주의:** PyMuPDF는 AGPL입니다(상용으로 쓰려면 Artifex 상용 라이선스 필요). 연구·PoC 단계에서는 문제없지만, 사내 서비스로 배포한다면 대안을 써야 합니다.
- pypdfium2: Apache-2.0/BSD
- docling-parse: MIT
- pdfplumber: MIT

## 3. 권장 파이프라인 (고정)

```
[0 선별] → [1 라우팅(쪽 단위)] → [2 추출(경로별)] → [3 구조화] → [4 검증·정규화] → 청킹(metadata-strategy.md)
```

### 3.0 선별 — 처리할 문서와 쪽 정하기 (LLM 없음)

- **라벨:** 프로그램·허가별 최신 판만 전체 처리합니다. 이전 판은 원문·해시만 보관하고, 필요할 때 차이(diff)만 처리합니다.
- **중복 허가 평가보고서:** 대표 문서만 처리합니다. 중복본은 거의 같은 문서인지 확인(MinHash 등)해서 연결만 기록합니다.
- **건너뛸 문서:** 목차 페이지(`review_index`), 직원 명단(`oeList`), 상표명 심사(`nameR`, 우선순위 낮음).
- **건너뛸 쪽:** 포장 그림 쪽은 판정 후 캡션과 텍스트 정도만 추출합니다.

### 3.1 라우팅 — 쪽 단위 판정 (쪽당 약 0.02초, 표 탐지 포함 시 약 0.1초)

| 경로 | 판정 신호 | 비중(실측 기준 추정) |
|---|---|---|
| `TEXT` | 텍스트층 충분, 표 없음 | 약 70% |
| `TEXT_TABLE` | 텍스트층 + 표 후보(선 그리기, 정렬된 숫자 열) | 약 25% |
| `IMAGE_PAGE` | 쪽 전체 이미지 + 텍스트층 없음(FDA 이미지 쪽) | 약 4% |
| `LEGACY_OCR` | producer가 "Paper Capture" 등이거나, 텍스트층 품질 점수가 낮음 | 약 1% |
| `ARTWORK` | 이미지 위주이고 텍스트 밀도 낮음(포장 그림, 서명 쪽) | 소량 |
| `HTML` | 확장자·콘텐츠 유형 | HC 심사 문서 |

텍스트층 품질 점수의 재료는 단어 쪼개짐 비율("t he"), 사전 단어 비율, 비정상 문자 비율입니다. 장식 배경 이미지는 "텍스트층 정상 + 이미지 면적 큼"으로 `TEXT`로 판정합니다.

### 3.2 경로별 추출

| 경로 | 1차 | 실패하면 |
|---|---|---|
| `HTML` | DOM 파서(제목 → 섹션, `<table>` → 표) | — |
| `TEXT` | 텍스트 블록 + 글꼴 정보 추출. 머리말·꼬리말 제거(반복 비율 기준), 줄 번호 제거, 하이픈 복원 | — |
| `TEXT_TABLE` | 표 구조 모델(TableFormer 등)로 셀 추출, 병합 셀 복원, 각주 연결 | 셀·숫자 검증에 실패한 표만 VLM |
| `IMAGE_PAGE` | 2배 렌더링 → 레이아웃 탐지 → 본문은 OCR(영어 모델), 표는 이미지 표 구조 인식 | 표 구조 신뢰도가 낮거나 체크박스가 있으면 VLM |
| `LEGACY_OCR` | 기존 텍스트층을 쓰되 품질 점수가 낮으면 재OCR | — |
| `ARTWORK` | OCR 텍스트만 저장(검색 가중치 낮게) | 선택적으로 VLM 설명 |

**VLM 단계 규칙 (qwen3.5:9B 또는 문서 전용 VLM)**
- 입력은 쪽 이미지에 "이 영역의 표를 마크다운으로" 같은 좁은 지시를 붙입니다.
- 출력의 숫자 토큰이 같은 쪽 OCR 토큰과 일치하는 비율이 기준치(예: 98%) 이상일 때만 채택합니다. 미달이면 OCR 결과를 쓰고 "검토 필요"로 표시합니다.
- 모든 블록에 `engine`(text_layer / ocr / table_model / vlm), `confidence`, `bbox`를 기록합니다. 이후 답변에서 "VLM이 추출한 수치는 원문 확인 필요" 같은 표시에 씁니다.

### 3.3 구조화 (섹션 트리와 말한 주체)

**섹션 트리 만들기**
- 1순위: PDF 책갈피. EMA 주 평가보고서, HC 제품설명서, FDA 일부 리뷰에 있습니다.
- 2순위: 번호 제목 패턴("2.2.", "3.1.1")과 글꼴 크기.
- 3순위: HTML 제목 태그.

**말한 주체 규칙(기관별로 수정)**

| 문서 | 규칙 |
|---|---|
| EMA 평가보고서 | `Discussion`·`Conclusion` 소절 → regulator. 결과 서술 → applicant_data |
| FDA 리뷰 | 기본값은 regulator. "The Applicant states/proposed/submitted/claims" 문장 → applicant. "Authors:"로 섹션 작성자(분야) 기록 |
| HC SBD/RDS | regulator |
| 라벨 | label |

**가림 처리:** FDA `(b)(4)`/`(b)(6)`, EMA `CCI` → `redacted=true`.

### 3.4 검증과 정규화

- **공통 출력:** 문서 JSON 하나에 블록 목록(쪽, 좌표, 유형, 섹션 경로, 엔진, 신뢰도)이 들어갑니다. Docling의 DoclingDocument 형식을 쓰면 별도 정의가 필요 없습니다.
- **문서별 품질 지표:**
  - 텍스트 확보율
  - OCR 평균 신뢰도
  - 탐지된 표 수 대비 구조화 성공 수
  - 숫자 셀 파싱률
  - 기준 미달이면 검토 대기열로 보냅니다.
- **캐시 키:** `(sha256, 쪽 번호, 엔진 버전)`. 새 제품이 들어오면 새 해시만 처리하고, 엔진을 바꾸면 해당 경로만 다시 처리합니다.

## 4. 라이브러리 추천

| 역할 | 1순위 | 대안 | 라이선스 |
|---|---|---|---|
| 전체 골격(레이아웃·표·OCR 연동·출처 좌표) | **Docling** | MinerU(표 성능 좋음, 라이선스 확인 필요) | Docling: MIT |
| PDF 텍스트·렌더링 | docling-parse / pypdfium2 | PyMuPDF(빠름, AGPL) | MIT / Apache·BSD |
| 표 구조(디지털·이미지) | Docling TableFormer | RapidTable, PP-StructureV3 | MIT / Apache |
| OCR(가벼운) | RapidOCR(영어 모델) | Tesseract | Apache |
| 문서 전용 VLM(쪽→마크다운) | granite-docling-258M | PaddleOCR-VL 0.9B | Apache |
| 범용 VLM(최후 단계) | qwen3.5:9B(Ollama, 비전 포함 빌드) | — | 모델 라이선스 확인 |

**Docling을 1순위로 꼽는 이유**
- 텍스트층이 있으면 그대로 쓰고, 이미지 영역만 OCR하는 혼합 방식이 기본 동작입니다.
- 결과에 쪽·좌표 출처가 남습니다. 근거 위치를 인용해야 하는 이 프로젝트에 직접 필요합니다.
- OCR 엔진(RapidOCR/Tesseract)과 VLM(로컬 Ollama 같은 API 엔드포인트 포함)을 설정으로 끼울 수 있습니다. 제안하신 3단계 구조를 그대로 담을 수 있습니다.

**단점과 대응**
- CPU에서 모든 쪽에 레이아웃·표 모델을 돌리면 쪽당 수 초가 걸립니다.
- 그래서 라우터가 `TEXT` 쪽은 빠른 경로로 보내고, `TEXT_TABLE`·`IMAGE_PAGE`만 Docling 모델 경로로 보내는 혼합 운영을 권장합니다. GPU가 있으면 전부 Docling으로 처리해도 됩니다.

**제외 권장:** Marker(GPL, 모델 가중치 상용 제한).

## 5. 예상 처리 속도 (제품 1개 추가 기준)

추정 근거: 실측(프로파일 쪽당 0.09초, RapidOCR 쪽당 약 2초)과 문서 규모입니다.

| 단계 | 쪽 수(선별 후) | 단가 | 시간 |
|---|---|---|---|
| 선별·라우팅 | 약 1,500 | 0.02~0.1초 | 1~3분 |
| `TEXT` 추출 | 약 1,000 | 0.02초 | 1분 미만 |
| `TEXT_TABLE` 표 모델 | 약 350 | CPU 2~4초 / GPU 0.3초 | CPU 12~25분 / GPU 2분 |
| `IMAGE_PAGE` OCR + 표 | 약 80 | CPU 3~6초 | 4~8분 |
| VLM 대체 처리 | 약 10~30 | GPU 10~40초 | 2~20분 |
| **합계** | | | **CPU 위주 약 20~50분, GPU가 있으면 약 10분** |

선별 단계(최신 라벨만, 중복 허가 제외)를 빼면 위 쪽 수가 약 2배가 됩니다.
