# 전처리 비교 시험 (정답 세트 30쪽)

작성일: 2026-10-09 · 관련: [전처리 실행 계획](preprocessing-plan.md) · 코드: `src/ra_prep/`, `eval/`

## 1. 원칙

- **전처리 파이프라인은 LLM을 호출하지 않습니다.** 사용하는 것은 Docling(레이아웃·표 구조 모델), RapidOCR, 그리고 규칙입니다. 같은 입력이면 같은 결과가 나옵니다.
- 이번 작업에서 Claude가 쓰인 곳은 **정답 세트를 만들 때 한 번**뿐입니다. 쪽 이미지를 직접 보고 정답을 적었으며, 파이프라인에는 들어가지 않습니다.
  - 정답은 후보 출력에서 시작해 원본 쪽 이미지와 칸 단위로 대조하며 고쳤습니다.
  - 따라서 정답은 "사람(이 경우 Claude)이 본 원문"이며, 작성자는 한 명입니다. 사람이 다시 확인하면 신뢰도가 올라갑니다(4장).

## 2. 정답 세트

`eval/gold/manifest.yaml`에 쪽 30개(쪽 PDF는 `eval/gold/pages/`, 정답은 `eval/gold/annotations/`)가 있습니다.

| 분류 | 쪽 | 내용 |
|---|---|---|
| EMA 디지털 표·본문 | g01, g02 | SB17 평가보고서 PK 표(병합 셀), 시험 설계 표 |
| EMA 워터마크 + 표 | g03, g06 | 철회된 중복 허가(Qoyvolma, Eksunbi). 대각선 워터마크 아래 표 이미지 |
| EMA 이미지 표 | g04, g05, g07 | 본문에 그림으로 붙은 PK·ADA·인구통계 표 |
| FDA 이미지 쪽 | g08–g17 | 텍스트층 없는 쪽: 시험 목록, 숫자 표(n(%), 검사치, 가림 표시), 본문, 체크박스 |
| FDA 디지털 | g18–g20 | 심사자 명단, 라벨 요약, 라벨 임상 표 |
| FDA 2009 스캔본 | g21–g23 | 문서에 내장된 옛 OCR 텍스트층 |
| FDA 글꼴 깨진 문서 | g24 | 텍스트층이 문자 치환 상태("LQWHUFKDQJHDEOH") |
| FDA 라벨 그림 쪽 | g25 | 사용설명서 그림 쪽 |
| HC 제품설명서 | g26–g28 | 디지털 표 |
| 가이던스 | g29, g30 | FDA 초안(줄 번호), HC 목차 쪽 |

정답 형식(쪽마다 JSON 1개):
- `text`: 본문 단락·제목·각주 목록(머리말·꼬리말 제외)
- `tables`: 표마다 행 목록. 병합 셀은 시작 칸에 한 번만 적습니다.
- `furniture`: 머리말, 꼬리말, 쪽 번호, 워터마크

## 3. 지표 (`eval/evaluate.py`)

| 지표 | 뜻 |
|---|---|
| text_recall | 정답 단락 중 출력에서 찾은 비율(퍼지 일치 95 이상) |
| cell_recall | 정답 표 칸 중 출력 표에 같은 칸으로 있는 비율(공백·대시·체크 기호 정규화 후 완전 일치) |
| num_cell_recall | 위와 같되 숫자가 든 칸만 |
| row_exact | 정답 행이 출력에서 그대로 재현된 비율(칸 순서 포함) |
| num_in_text | 숫자 칸의 값이 출력 어딘가에 있는 비율(표 구조 없이도 검색에 걸리는지) |
| garbled | 깨진 조각이 이어지는 출력 블록 수 |
| furniture_leak | 머리말·꼬리말 등이 본문 블록으로 남은 수 |
| sec_per_page | 쪽당 처리 시간(CPU 4코어) |

## 4. 후보

| 후보 | 구성 |
|---|---|
| A0 | Docling + 쪽 단위 경로 판정(경로별 OCR 설정) + 워터마크 제거 |
| A1 | A0 + 두 번째 OCR 판독. 깨진 줄은 다시 읽어 교체하고, 그림으로 잡힌 표 이미지는 표로 복원 |
| **A1S** | **A1 + RA 후처리(머리말·꼬리말, 섹션, 말한 주체, 가림 표시, 칸 정리). 최종안** |
| A2 | A1과 같되 2009 스캔본은 내장 텍스트층 대신 다시 OCR |
| B | PaddleOCR-VL 1.6 (문서 전용 0.9B 모델, CPU). OCR이 필요한 16쪽에만 실행 |
| C | 기준선: PyMuPDF 텍스트·표 추출 + 이미지 쪽은 RapidOCR 줄 단위(표 구조 없음) |

시간은 CPU 4코어 기준입니다. 다른 작업이 코어 1개를 쓰는 상태에서 쟀습니다. 쪽 1장짜리 PDF를 하나씩 처리한 값이라 문서 단위 처리보다 쪽당 시간이 큽니다(문서 단위 실측은 8장).

## 6. 시험이 바꾼 것 (정답 세트로 찾은 문제와 대응)

| 문제 | 영향 | 대응 |
|---|---|---|
| EMA 철회 제품 문서의 대각선 워터마크가 텍스트 객체로 표 이미지 위에 있음 | 판정기가 "텍스트가 있는 이미지"로 보고 OCR을 건너뜀 → 표 전체 누락(g03, g06) | `sanitize`: 기울어진 텍스트 객체 제거 후 판정 |
| 표 이미지 가장자리에 캡션이 겹침 | 같은 이유로 OCR 누락 | 이미지 덮임 판정을 "글자 상자 면적 비율 ≥ 8%"로 변경 |
| Docling이 표 이미지를 그림으로 분류 | 표 구조 없음, 숫자가 흩어짐(g05: 칸 0/68) | `grid`: 그림 영역의 OCR 줄 위치로 표 재구성 → 62/68 |
| Docling OCR이 줄 하나를 깨뜨림 | 심사자 판단 문장 등이 깨짐 | `reocr`: 두 번째 판독과 비교, 의심 블록은 다른 배율로 잘라 다시 읽고 가장 자연스러운 판독 선택. 깨진 줄 4 → 1 |
| FDA 문서 일부의 글꼴 매핑 깨짐("LQWHUFKDQJHDEOH") | 텍스트층이 쓰레기 | 문자 삼중자 통계로 판정 → 전체 쪽 OCR(14쪽) |
| 머리말·꼬리말·쪽 번호·줄 번호 | 본문 블록 100개 오염 | `structure`: 패턴 + 반복 + Docling furniture 층 → 0 |

## 7. 판단

1. **최종안은 A1S입니다.** 디지털 쪽은 사실상 완전하고(칸 99.8%), 이미지 쪽도 숫자 칸 94.8~97.9%를 맞춥니다. 숫자 값이 출력 어딘가에 있는 비율(num_in_text)은 98% 이상이라, 표 구조가 틀린 경우에도 검색에는 걸립니다.
2. **2009 스캔본은 내장 텍스트층을 유지합니다(A2 기각).** 다시 OCR해도 Docling이 표 칸에는 내장 텍스트층을 쓰기 때문에 결과가 같고, 시간만 약 3배가 됩니다. 남은 오류("lnfliximab", "svndrome")는 원본 OCR층 자체의 오류입니다.
3. **PaddleOCR-VL은 지금은 채택하지 않고, GPU 환경의 선택 엔진으로 남깁니다.** 표 구조(행 일치 +11.5%p)는 확실히 낫지만 CPU에서 14배 느립니다. 계획의 채택 기준("이미지 표에서 5%p 이상 좋고 시간 허용")에서 시간 조건을 넘지 못합니다. GPU가 생기면 `IMAGE` 쪽의 표만 B로 처리하는 경로를 비교합니다.
4. **남은 약점과 보완 방법**
   - 행 병합 라벨이 있는 이미지 표(g12)와 체크박스 서식(g17): 구조 정확도가 낮습니다. 해당 블록은 숫자 판독 불일치 시 `needs_review`로 표시됩니다.
   - 스캔본 내장 OCR층 오류: 그대로 둡니다. 해당 쪽은 Stelara 원 허가 심사 문서의 스캔본 130쪽뿐입니다.
   - 목차 쪽(g30): 줄 형식이 달라 일치율이 낮지만 검색 가치가 낮아 그대로 둡니다.

## 8. 실제 문서 처리 시간 (SB17, CPU 4코어, `ra-prep run`)

| 문서 | 쪽 | 경로 | 시간 | 초/쪽 | 검토 필요 블록 |
|---|---|---|---|---|---|
| EMA 평가보고서(Pyzchiva) | 168 | DIGITAL 112, MIXED 52, IMAGE 4 | 827초 | 4.9 | 18 |
| FDA BMER | 152 | DIGITAL 101, IMAGE 36, MIXED 15 | 807초 | 5.3 | 20 |
| HC 제품설명서 | 99 | DIGITAL 76, MIXED 23 | 332초 | 3.4 | 1 |
| HC SBD(HTML) | 1 | HTML | 0.1초 | – | 0 |

- 시간 구성(EMA 평가보고서): OCR 없는 Docling 171초(쪽당 1.5초), OCR이 필요한 쪽의 Docling 481초(쪽당 8.6초), 두 번째 판독 173초.
- FDA BMER는 두 번째 판독을 그림 영역으로 한정하기 전에 측정했습니다. EMA 평가보고서는 한정 후 측정이며, 두 번째 판독 시간이 268초에서 173초로 줄었습니다. 정답 세트 점수는 그대로입니다(칸 95.8 → 95.7, 1칸 차이).
- **제품 1개 예상:** 선별 후 약 1,000~1,400쪽 × 쪽당 4~5초 ≈ **1.2~2시간(CPU 4코어)**. 우스테키누맙 5개 제품과 Stelara, 가이던스까지 전체 7,952쪽은 약 10시간입니다.
- 더 빠르게 하려면, 효과가 큰 순서로:
  1. GPU(Docling 레이아웃·표 모델; `--device cuda`)
  2. 문서 단위 병렬 처리(코어 수만큼 프로세스)
  3. OCR 쪽 표 모델을 fast 모드로 전환(정답 세트 재측정 필요)

결과물 예시(문서 1개 = JSON 1개, `data/parsed/<sha256>.json`): 블록마다 쪽·좌표·유형(text/table)·섹션 경로·말한 주체·출처(text_layer/ocr/html)·상태(kept/reread/needs_review)·가림 표시·시험 ID가 붙고, 문서마다 QA 지표가 붙습니다. 청킹 단계는 이 파일만 읽으면 됩니다.
