# 진행 계획 — 바이오시밀러 RA Agentic RAG

작성일: 2026-10-08 · 상태: 확정 반영(마감 없음, 최대한 빠르게 진행 — 주차는 순서 의미로만 사용)
관련 문서: [RA 문서 소스 카탈로그](ra-document-sources.md)

## 1. 범위

| 항목 | 내용 |
|---|---|
| 성분 | ustekinumab (대조약 Stelara) |
| 제품 | SB17, ABP 654, CT-P43, BMAB1200, BAT2206 |
| 기관 | EMA, FDA, Health Canada |
| 문서 축 | 제품 심사자료·라벨 + 가이던스(시점·상태 관리) |
| 쟁점 | 전 범위: 분석적 동등성, PK·대조약 브리징, 비교임상, 면역원성, 외삽, 인터체인저빌리티, 제형 |
| 후속 | 선례 확장 검색(예: guselkumab → ustekinumab 선례) |

### 1.1 제품 × 기관 현황

아래 표는 2차 출처 기준입니다. 1단계에서 공식 데이터로 교체합니다.

| 코드 | 개발사 (판매 파트너) | FDA | EMA | HC |
|---|---|---|---|---|
| SB17 | Samsung Bioepis (US: Sandoz) | Pyzchiva (ustekinumab-ttwe), 2024-06 | Pyzchiva, 2024-04 | Pyzchiva, 2024-08 |
| ABP 654 | Amgen | Wezlana (ustekinumab-auub), 2023-10, 인터체인저블 | **Wezenla**, 2024-06 | Wezlana, 2023-12 |
| CT-P43 | Celltrion | Steqeyma (ustekinumab-stba), 2024-12 | Steqeyma, 2024-08 | Steqeyma, 2024-07 |
| BMAB1200 | Biocon | Yesintek (ustekinumab-kfce), 2024-12 | Yesintek, 2025-02(발표일). **EU 적응증에 UC 없음** | Yesintek, 2025-10 |
| BAT2206 | Bio-Thera (US: Hikma, EU: Gedeon Richter) | **Starjemza** (ustekinumab-hmny), 2025-05 | **Usymro**, 2025-08 | **승인 확인 안 됨** |

이 현황에서 데모와 평가에 쓸 수 있는 사례가 나옵니다.

- **이름 불일치 테스트:** ABP 654(Wezlana/Wezenla), BAT2206(Starjemza/Usymro)은 이름만으로 연결하면 실패합니다.
- **"자료 없음" 처리 테스트:** BAT2206 × HC 칸에서 시스템이 없는 정보를 지어내지 않는지 확인합니다.
- **기관별 적응증 차이:** BMAB1200은 EU에 UC가 없습니다. 기관 간 차이를 정당한 차이로 설명할 수 있어야 합니다.
- **가이던스 변화와 선례의 연결:** Wezlana의 인터체인저블 지정과 FDA의 스위칭 연구 요구 변화(2019 최종 → 2024 초안)가 맞물립니다.
- **신규 제품 추가 측정:** BAT2206은 가장 최근에 승인된 제품입니다. 개발 중에는 빼 두었다가 마지막에 추가해 "새 제품 추가 수작업"을 측정하는 용도로 씁니다(확인 필요, 6장).

## 2. 단계별 계획

주차는 6주를 가정한 예시입니다. 4주로 줄여야 하면 5장의 축소안을 따릅니다.

### 0단계 — 준비 (1주차 전반)

| 작업 | 완료 기준 |
|---|---|
| 네트워크 허용: EMA, FDA, HC, ClinicalTrials.gov, DailyMed, Federal Register | 수집기가 각 사이트에서 200 응답을 받음 |
| 저장소 골격: Python 프로젝트, PostgreSQL + pgvector, 설정·로그 구조 | 로컬에서 DB 기동, 빈 스키마 생성 |
| LLM·임베딩 모델 고정 | 모델과 버전을 문서화. 비용·지연 측정이 가능한 상태 |
| **질문 세트 v0** (유형별 15~20개) + **데모 시나리오 3개** 초안 | 질문마다 유형, 기대 근거 문서, "어떤 구성요소가 도움이 돼야 하는가" 가설이 붙음 |

질문 세트를 먼저 만드는 이유는 무엇을 수집하고 파싱해야 하는지가 질문에서 정해지기 때문입니다.

### 1단계 — L0 사전 정보 테이블 + 문서 발견 (1주차 후반 ~ 2주차 초)

| 작업 | 소스 |
|---|---|
| EMA 제품·문서 목록 수집 | E1, E2 |
| FDA 제품·신청·문서 목록 수집 | F1, F2 |
| HC 제품·허가 목록 수집 | H1, H2 + SBD/RDS 페이지 확인 |
| 시험 등록 정보 | X1 |
| `program`(5행), `registration`(최대 15행) 채우기. 프로그램 간 대응은 사람이 확인해서 고정 | — |
| **문서 가용성 매트릭스**: 5 × 3 칸마다 어떤 문서가 실제로 공개돼 있는지 | — |
| 소스 카탈로그의 ⚠️ 항목 검증(Purple Book 헤더, DPD 바이오시밀러 플래그, EMA URL 덮어쓰기 등) | — |

**완료 기준**
- L0 테이블이 공식 데이터로 채워짐
- 문서 가용성 매트릭스 완성
- 카탈로그 갱신

**판단 지점:** FDA 리뷰 문서가 공개되지 않은 제품이 많으면(최근 승인된 Steqeyma, Yesintek, Starjemza가 해당될 수 있음), 그 칸을 쓰는 질문을 바꿉니다.

### 2단계 — L1 원문 보관·파싱 + 가이던스 수집 (2주차)

| 작업 | 완료 기준 |
|---|---|
| 다운로드·버전 관리((URL, sha256), 수집일) | 재실행해도 중복이 생기지 않음 |
| 페이지별 텍스트층 검사 → `text_layer_ratio`, `ocr_pages` 기록. 필요한 페이지만 OCR | **스캔본 비율 리포트**("FDA는 스캔본이 많다" 가설 검증) |
| 섹션 구조 파싱(EPAR PDF, FDA 리뷰 PDF, HC SBD HTML), 표 추출 | 문서별 섹션 트리. 표 10개를 원문과 대조해 점검 |
| 말한 주체 1차 태깅(문서 구조 기반) | 샘플 문서에서 태깅 결과를 사람이 점검 |
| 가이던스 수집(카탈로그 3장 시작 목록) + 상태·날짜·적용 범위 필드 + 섹션 단위 분할 | 가이던스마다 `status`, `effective_from`, `supersedes`가 채워짐 |

### 3단계 — L2 검색 + 일반 RAG 기준선 + 평가 도구 (3주차)

| 작업 | 완료 기준 |
|---|---|
| 청크 생성 + 컨텍스트 헤더(제품·기관·문서·날짜·섹션 경로·말한 주체) | 모든 청크에 메타데이터가 붙음 |
| 키워드 + 벡터 하이브리드 검색, 메타데이터 필터, 제품별 분해 검색, 리랭커 | 검색 단위 테스트 통과 |
| **한국어 질문 → 영어 문서** 대응: 다국어 임베딩, 질의를 영어 용어로 재작성 | 한국어 질문으로 필수 근거를 회수함 |
| **일반 RAG 기준선**(약하게 만들지 않음: 필터·키워드·리랭커 포함) | 질문 세트 전체 실행 |
| 평가 도구: 정답 근거 목록, 근거 회수율, 인용 정확도, 수치 혼입, 비용·지연 기록 | **기준선 점수 v0** |

### 4단계 — Agentic RAG + L3 필드 추출 (4주차 ~ 5주차 초)

| 작업 | 완료 기준 |
|---|---|
| 도구: `resolve_product`, `list_documents`, `search_guidance(as_of)`, `search_precedents`, `get_source_excerpt`, `extract_field`(필요할 때만, 캐시), `validate_evidence` | 도구별 단위 테스트 |
| 질의 해석: 엔티티·기관·시점(당시/현재)·질문 유형 | 데모 질문에서 해석 결과가 맞음 |
| 근거 부족·충돌 시 재검색, 종료 조건, 호출 한도 | 실행 로그에 판단 근거가 남음 |
| 답변 형식: 기관·시점 명시, 인용, 초안/최종 표시, 원문 사실·기관 판단·시스템 의견 구분 | 데모 시나리오 3개가 끝까지 동작 |

### 5단계 — 평가·데모 정리 (5주차 ~ 6주차)

| 작업 | 완료 기준 |
|---|---|
| 비교 실행: 수작업 / 일반 RAG / Agentic RAG / Agentic + L3 카드 | 질문별로 짝지어 비교. 여러 번 실행해 결과가 얼마나 흔들리는지 기록 |
| 신규 제품 추가 측정: BAT2206 적재에 드는 사람 시간과 실패 지점 | 수동 개입 시간 리포트 |
| 데모 화면(간단한 웹 UI): 질문 → 메모·비교표 → 원문 위치 확인 | 리허설 완료 |
| 평가 보고서: 지지된 가설과 지지되지 않은 가설, 비용, 한계 | 보고서 |

### 후속 — 선례 확장 검색

- 성분 속성 프로파일과 쟁점별 "참고 가능 / 불가" 규칙을 만듭니다.
- guselkumab 질문으로 시연합니다.
- 4단계 도구 구조에 `expand_precedents`를 추가하는 방식이라, 본 계획의 구조를 바꾸지 않고 붙일 수 있습니다.

## 3. 데모 시나리오 후보

| # | 질문 | 보여주는 것 | 주로 쓰는 층 |
|---|---|---|---|
| D1 | "5개 제품의 기관별 이름·허가일·적응증 차이를 정리해줘" | 이름 불일치 해소, BMAB1200 EU UC 미포함, BAT2206 HC "승인 확인 안 됨" | L0 |
| D2 | "이 제품들은 비교임상(3상)을 했나? 지금 기관별로 신청한다면 필요한가?" | 당시(2023~2025 심사) vs 현재(EMA 2026 최종, HC 2026-05 최종, FDA 2025-10 초안), 상태 라벨 | L1 가이던스 + L3 |
| D3 | "Wezlana는 어떤 근거로 인터체인저블로 지정됐나? 스위칭 연구가 필요했나?" | 선례와 가이던스 변화(2019 최종 → 2024 초안)의 연결 | L1 + L2 + 에이전트 |
| D4 | "5개 제품의 PK 시험 설계(대상, 대조약 출처, 브리징)를 비교해줘" | 시험·집단·대조약 구분, FDA Q&A Rev 4(비미국 대조약)와의 연결 | L3 + 비교표 |
| D5(후속) | "guselkumab 바이오시밀러 개발에 참고할 선례는?" | 선례 확장 검색, 이전 가능 범위 표시 | 후속 |

**확정: D2, D3, D4.** D1은 L0 테이블로 자연스럽게 함께 보여주고, D5는 후속입니다.

## 4. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 네트워크 접근 불가(현재 세션은 기관 사이트 403) | 1단계 이후 전부 지연 | 0단계 첫 작업으로 해결. 안 되면 로컬에서 원문을 받아 업로드 |
| 최근 승인 제품의 FDA 리뷰 미공개 | FDA 칸이 비어 질문 축소 | 1단계 문서 가용성 매트릭스로 조기 확인. HC SBD·EPAR로 대체 |
| FDA 스캔본 비율이 높음 | OCR 시간·오류 증가 | 2단계에서 측정. 로컬 OCR 우선, 표만 비전 모델 |
| 평가 정답 작성 부담(사람 시간) | 숨은 최대 비용 | 질문 수를 15~20개로 제한. 정답은 "필수 근거 위치 목록" 위주로 작성 |
| RA 전문가 검토 불가 | 규제 해석 품질을 검증할 수 없음 | 해당 항목은 "미검증"으로 보고. LLM 자기평가로 대체하지 않음 |
| 한국어 질문과 영어 문서의 불일치 | 검색 누락 | 3단계에서 질의 재작성·다국어 임베딩을 기준선에도 동일하게 적용 |

## 5. 기간 축소안 (4주)

| 주 | 내용 |
|---|---|
| 1주 | 0단계 + 1단계(L0는 EMA·FDA 우선, HC는 SBD 목록만) |
| 2주 | 2단계(가이던스는 비교임상·인터체인저빌리티 관련 문서만) |
| 3주 | 3단계 + 4단계 핵심 도구(데모 시나리오 2개 기준) |
| 4주 | 5단계(신규 제품 추가 측정은 생략 가능) |

## 6. 확정된 사항 (2026-10-08)
