# 시험 세트 정리

작성일: 2026-10-11

이 프로젝트의 성능 수치는 모두 아래 두 시험 세트에서 나왔습니다. 두 세트 모두 작고, 작성자는 한 명(Claude)이며, 사람이 아직 검토하지 않았습니다. 수치를 인용할 때는 6장의 한계를 함께 봐야 합니다.

| | 1. 전처리 정답 세트 | 2. 검색 정답 세트 |
|---|---|---|
| 무엇을 재나 | PDF → 텍스트·표 추출이 원문과 같은가 | 질문에 대한 근거 청크를 찾아오는가 |
| 위치 | `eval/gold/` (manifest, 쪽 PDF 30개, 정답 JSON) | `eval/retrieval/questions.yaml` (+ `corpus_docs.txt`) |
| 규모 | 30쪽: 본문 단락 301, 표 칸 1,190(숫자 808), 표 행 326 | 20문항, 근거 묶음 45개(채점 18문항·41묶음) |
| 정답 형식 | 쪽마다 본문·표·머리말 목록 | 문항마다 근거 묶음, 묶음마다 (문서, 쪽, 원문 인용) |
| 채점 코드 | `eval/evaluate.py` | `eval/retrieval/compare_chunking.py`, `rerank_test.py` (검증: `check_gold.py`) |
| 결과 문서 | [전처리 비교 시험](preprocessing-benchmark.md) | [청킹·임베딩 전략](chunking-strategy.md) 7·8장 |
| 쓰인 결정 | 추출 방식 A1S 확정, OCR 후보 비교 | 청크 V2 확정, 행 청크 제외, 헤더 유지, 재순위 도입 |

## 1. 전처리 정답 세트 (30쪽)

- **목적:** 쪽 유형별로 추출 품질을 잽니다. 쪽 유형은 디지털, 워터마크, 이미지 표, 스캔본, 글꼴 깨짐, 라벨 그림입니다.
- **구성:** EMA 7쪽, FDA 18쪽, HC 3쪽, 가이던스 2쪽. 분류와 각 쪽 내용은 [전처리 비교 시험](preprocessing-benchmark.md) 2장에 있습니다.
- **만든 방법:** 후보 출력(A1)에서 시작해, 쪽 이미지와 칸 단위로 대조하며 고쳤습니다. 숫자 값은 모두 이미지로 확인했습니다.
- **지표:**
  - text_recall: 퍼지 일치 95 이상
  - cell_recall, num_cell_recall, row_exact
  - num_in_text, garbled, furniture_leak, 쪽당 시간
- **이 세트에 없는 것:** 텍스트층에서 글자가 깨지는 FDA 문서 유형(U+FFFD, 29칸 밀린 글꼴)은 정답 세트에 없었습니다. 그래서 점수에 드러나지 않았고, 검색 정답 세트를 만들다가 발견했습니다(전처리 비교 시험 9장). 이 유형의 교정 효과는 문서별 깨진 글자 수로만 재었습니다.

## 2. 검색 정답 세트 (20문항)

### 2.1 목적과 형식

- **목적:** 청킹·검색 방식 비교. 답변 문장의 품질이 아니라 "반드시 찾아야 하는 근거 위치"를 정답으로 둡니다.
- **근거 묶음:** 하나의 관점입니다(예: EMA 근거, FDA 근거, 제품별 근거). 묶음 안의 근거 중 하나만 찾으면 그 묶음을 맞힌 것으로 봅니다.
- **채점:** 검색된 청크가 같은 문서이고, 정규화(NFKC, 소문자, 공백 제거)한 청크 텍스트에 인용문이 들어 있으면 찾은 것입니다. 청킹 방식이 달라도 같은 기준으로 채점됩니다.
- **지표:**
  - 재현율@k: 찾은 묶음 / 전체 묶음
  - 부모 포함 재현율@k: 검색된 청크의 부모(절·표 전체) 안에 있으면 찾은 것. 답변 단계에서 실제로 읽는 범위입니다
  - 완전 정답 문항 수: 모든 묶음을 찾은 문항
  - LLM이 읽을 토큰 수
  - 다른 제품 혼입률

### 2.3 검색 대상 코퍼스 (시험 때 고정, 58건)

`eval/retrieval/corpus_docs.txt`. 시험 도중에도 전처리 문서가 늘어나기 때문에, 같은 조건으로 비교하려고 고정했습니다.

| 기관 | 문서 |
|---|---|
| EMA | 평가보고서 4(제품마다 1), 가이던스 5 |
| FDA | 심사 문서 23(SB17 7, CT-P43 6, ABP654 5, BMAB1200 5), 허가 서한 1(SB17), 가이던스 21 |
| HC | SB17 제품설명서 1, SB17 SBD 1, 가이던스 2 |

라벨, 대부분의 허가 서한, SB17 외 제품의 HC 문서는 아직 들어 있지 않습니다. 실제 운영 코퍼스보다 작고 문서 유형도 치우쳐 있습니다.

### 2.4 만든 방법

1. 데모 시나리오 D2~D4에서 질문을 뽑았습니다(Claude 작성).
2. 근거 후보를 `eval/retrieval/locate.py`(전처리 결과에 대한 키워드 검색)로 찾았습니다.
3. 원문 블록을 읽고 근거를 확정했습니다.
4. `check_gold.py`로 모든 인용문이 해당 문서·쪽에 실제로 있는지 확인했습니다(누락 0).

## 3. 결과 요약 (검색 정답 세트, 한국어 질문, 라우팅 적용)

| 구성 | 부모 포함 재현율@5 | 부모 포함 재현율@10 |
|---|---|---|
| V2 청크, 혼합 검색 | 43.9% | 63.4% |
| + 용어집 확장 | 58.5% | 70.7% |
| + 재순위(후보 30) | 70.7% | **78.0%** |
| 참고: 같은 조건, 라우팅 없음(전체 검색, 용어집 없음) | – | 51.2% |

세부 표는 [청킹·임베딩 전략](chunking-strategy.md) 7·8장과 `eval/retrieval/results/`에 있습니다.

## 4. 재현 방법

```bash
P=.venv-prep/bin/python
$P eval/evaluate.py A1S C                        # 전처리 정답 세트 채점 (후보 출력은 eval/candidates.py)
$P eval/retrieval/check_gold.py                  # 검색 정답 세트 인용문 확인
$P eval/retrieval/compare_chunking.py            # 청킹 변형 비교 (bge-m3 임베딩, CPU에서 1~2시간; 캐시 사용)
$P eval/retrieval/rerank_test.py --depth 30      # 재순위 시험 (CPU에서 약 40분)
```

임베딩과 재순위 점수는 `data/emb_cache/`에 캐시되며, 이 폴더는 git에 넣지 않습니다.

## 5. 정답 세트를 늘릴 때

- 문항을 추가할 때 같은 형식(묶음 + 인용문)을 쓰고, `check_gold.py`로 확인합니다.
- **튜닝에 쓰지 않은 별도 문항**을 만들어 최종 확인에 씁니다(6장의 과적합 문제).
- 사람 검토 후 `status: reviewed`로 바꿉니다.

## 6. 한계 (수치를 읽을 때 반드시 고려)

1. **작다.**
   - 검색 세트는 묶음 하나가 2.4%p라서 5%p 안쪽 차이는 우연일 수 있습니다.
   - 전처리 세트도 30쪽(OCR 쪽 16쪽)이라 1~2%p 차이는 의미가 없습니다.
2. **작성자가 한 명이고 사람 검토가 없다.** 질문, 근거, 표 정답 모두 Claude가 작성했습니다. 상태가 `located`이고 `reviewed`가 아닙니다. RA 담당자가 근거가 맞는지, 빠진 근거가 없는지 봐야 합니다.
3. **같은 세트로 고르고 고쳤다(과적합 위험).** 아래는 모두 이 20문항의 실패를 보고 만든 규칙이라, 이 세트에서는 점수가 실제보다 높게 나올 수 있습니다.
   - 라우터의 "각 제품" 규칙, "FDA는" 같은 조사 처리, "EU-Stelara" 제외
   - 용어집(`config/query_glossary.yaml`): 일반 RA 용어로 적었지만 질문을 본 뒤 작성
   - 머리말 누락 수정

   새 문항으로 다시 확인해야 합니다.
4. **근거를 키워드 검색으로 찾았다.** `locate.py`로 찾을 수 있는 근거 위주로 정답이 정해졌습니다. 다른 표현으로 쓰인 근거가 빠졌을 수 있고, 그 경우 재현율이 실제보다 낮게 나옵니다.
5. **전처리 결과 위에서 만들었다.** 전처리가 놓친 내용(그림 속 글자, 남은 깨진 기호)은 정답에 들어갈 수 없습니다. 전처리 오류가 검색 점수에 드러나지 않습니다.
6. **코퍼스가 고정·부분적이다(58건).** 라벨과 허가 서한이 들어오면 비슷한 문장이 늘어 검색이 더 어려워질 수 있습니다.
7. **답변 품질은 재지 않았다.** 근거를 찾는 단계까지만 쟀습니다. LLM 답변의 정확성, 인용, "모른다" 처리(Q18)는 별도 시험이 필요합니다.
